## rust语言特性
1. `#![no_std]` 为什么要写？
  rust程序大多时候是需要强大std标准库来进行rust程序编写，但当操作系统提供不了std库运行的环境时（比如现在编写裸机程序就是抛弃了操作系统的支持），这是告诉编译器不要链接和启用std库而只使用core库。使用core库一位置必须自己提供_start入口和#[panic_handler](是[no_main]要求的必须自写_start)。
2. `#![no_main]` 为什么要写？
  ？main函数入口需要运行时环境（c runtime和rust runtime），其依赖操作系统支持；
3. `#[cfg(target_arch = "riscv64")]` 是干什么的？
  面向risc-v64架构(只有当前编译目标架构是 RISC-V 64 位时，才保留并编译*被它修饰的代码*)
4. `ELF`是什么？
  “可执行可链接格式”。类似于windows的.exe
5. 🤷‍♂️🤷‍♂️🤷‍♂️ `unsafe extern "C" fn _start() -> !` 每个词是什么意思？
  unsafe：“不安全”。告诉编译器绕开静态安全检查（X``进入 Rust 无法完全证明安全的区域，仍然保留大量检查``），笔者自己保证编译上的安全。
  extern "C"：遵循C ABI约定，即业界通用的二进制约定，让编译器用字标准来生成函数
  _start:裸机程序的启动入口，需要在此完成栈空间的设置，随后立即跳转rust_main
  -> !:没有返回值且永远没有返回值，这符合裸机启动到结束的逻辑。
6. `const` 和 `static mut` 有什么区别？
  const:常量，主要是在编译期保持不变的量（类似于“贴纸标签”，在编译器看到一个const变量就用其值去“粘贴”它），到运行期不见踪迹
  static:静态变量，主要是在运行期保持不变的量（``应该是拥有固定存储位置和 'static 生命周期的全局对象``）。静态是指在程序运行期间“内存地址的绝对不变性”。，不允许他人修改其地址，但可以更改其内容
  mut:内容可变=>static mut：在一开始就开辟一块固定不变的空间地址来存放该变量，同时其内容可变，可被访存
7. `[u8; 4096]` 是什么？
  无符号8位数（0~255）X4096个的数组
8. `b"Hello"` 和 `"Hello"` 有什么区别？
  `b"Hello"`：字节串字面量。等价于&[0x48,0x65,0x6C,0x6C,0x6F](数字为ASCII码的值)。“b”可以理解为rust的语法糖
  `"Hello"`：字符串字面量
9. `*c` 是什么？
  对c这个空间地址进行解引用，取地址上存放的值/内容
10. `shutdown(false)` 为什么没有分号？ `#[panic_handler]` 为什么必须有？
  遵循rust的函数语法，作为rust_main函数的返回值不需要“;”。
11. `naked_asm!` 为什么有感叹号？
  “宏调用标记”，汇编宏
12. `#[unsafe(naked)]` 为什么和栈有关？
  若是非裸机程序，编译器在遇到普通函数时会尝试生成函数序言和尾声，甚至有可能尝试访问栈空间。而在这里的_start裸机程序之前甚至都没有配置栈，故而会出现非法访存
1.  `'static`这里static前面的“'”是什么意思？
  这是rust对生命周期的定义的标记，是正经代码的语法而不是控空虚的概念。

## 3.3 裸机启动流程
> 你在宿主机/远程容器里敲 cargo build 或 cargo run
>        ↓
>Cargo 先编译并执行 build.rs
>        ↓
>build.rs 生成链接脚本 linker.ld
>        ↓
>Cargo 调 rustc 编译 src/main.rs 为 RISC-V 目标程序
>        ↓
>链接器把程序段按 linker.ld 放到指定地址
>        ↓
>cargo run 再调用 QEMU
>        ↓
>QEMU 加载这个 RISC-V 程序并“像一台机器一样”跑起来
>        ↓
>真正的裸机程序开始执行：_start -> rust_main -> shutdown
